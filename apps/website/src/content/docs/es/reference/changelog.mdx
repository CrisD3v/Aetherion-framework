Todos los cambios notables de este proyecto se documentarán en este archivo.

## [1.3.0] - 2026-10-01

### Añadido
- **CLI:** Nuevo comando `aetherion bundle` que proporciona un pipeline de empaquetado nativo: `tsc` → generación de entry point → `esbuild` → `archiver` (zip).
- **CLI/Deploy:** Validación automática de credenciales AWS (`check-env`) se ejecuta antes de la síntesis, abortando tempranamente si faltan credenciales.
- **Core:** Nueva sección `build` en `AetherionConfig` para controlar la compilación de TypeScript y el pipeline de empaquetado.
- **Core:** Nueva sección `backend` en `AetherionConfig` para configurar estado remoto de Terraform con S3 + DynamoDB state locking.
- **Infra:** Soporte para S3 Backend con DynamoDB state locking, previniendo corrupción de estado cuando múltiples desarrolladores despliegan simultáneamente.
- **CLI/Workspace:** ¡Aislamiento de espacio de trabajo! Todos los artefactos generados, builds, bundles (`.zip`) y `cdktf.out` (incluyendo backups de Terraform) ahora se ocultan limpiamente dentro de la carpeta `.aetherion`. Tu directorio raíz se mantiene limpio y sin basura. `aetherion init` ahora genera automáticamente un `.gitignore` que ignora `.aetherion`.

### Solucionado
- **Infra:** (FIX-001) Las funciones Lambda ahora usan `app.zip` del proyecto en vez del placeholder `dummy.zip` cuando está disponible.
- **Infra:** (FIX-002) Se añadió `sourceCodeHash` a todos los recursos `aws_lambda_function`. Terraform ahora detecta correctamente los cambios de código y actualiza las Lambdas en despliegues posteriores.
- **CLI:** (FIX-003) El comando deploy ahora usa el pipeline de empaquetado nativo en vez de delegar a `npm run build`, que previamente eliminaba los metadatos de decoradores cuando se usaba `esbuild` directamente sobre el código TypeScript.
- **CLI:** (FIX-003) Entry point de Lambda autogenerado con enrutamiento `AETHERION_TARGET_CLASS`. Los usuarios ya no necesitan crear manualmente un archivo `index.ts` de enrutamiento — el framework lo genera durante el paso de empaquetado.

### Cambiado
- **CLI/Deploy:** El paso de compilación en `aetherion deploy` ahora ejecuta el pipeline nativo completo (tsc → esbuild → zip) en vez de un genérico `npm run build`.
- **Arquitectura:** ¡Transición a una verdadera Arquitectura Lambda 1:1! `aetherion bundle` ahora evalúa el AST, aísla los decoradores y empaqueta cada método controlador en un minúsculo `.zip` completamente independiente.
- **Core/Env:** Variables de Entorno con Menor Privilegio (Least Privilege). El framework ahora filtra agresivamente `process.env` durante el despliegue, inyectando únicamente las variables explícitamente solicitadas en `envKeys` dentro de cada Lambda.
- Todos los paquetes actualizados a la versión 1.3.0.

## [1.2.0] - 2026-09-30

### Añadido
- **Core:** Se agregaron campos extendidos en `AetherionConfig` (`stage`, `projectName`, `lambdaDefaults`) dentro de `defineConfig`.
- **Core:** Soporte para `CognitoUserPoolClient` en los decoradores de `@Infra`.
- **Core:** Soporte para Global Secondary Indexes (GSIs) y Sort Keys en DynamoDB mediante `@DynamoTable`.
- **Core:** Soporte mejorado del esquema IAM a través de `@IamPermissions` aceptando tanto formato nativo de AWS como mapas de objetos heredados.
- **CLI:** Comando nativo `aetherion validate` para comprobar el entorno y prerrequisitos de construcción.
- **CLI:** Comando nativo `aetherion status` para introspeccionar `terraform.tfstate` y listar los recursos desplegados activos (Endpoints, Cómputo, DBs).
- **CLI:** Comando nativo `aetherion destroy` con confirmaciones de seguridad.
- **CLI/Init:** `aetherion init` ahora autogenera los archivos `.env` y `.env.example`.

### Cambiado
- **CLI/Deploy:** Refactorización importante del flujo de despliegue. `aetherion deploy` ahora es un comando "todo en uno" que ejecuta la compilación, la síntesis y la aplicación de terraform automáticamente.
- **CLI/Deploy:** El CLI ahora invoca a `terraform` directamente, eliminando la dependencia problemática del envoltorio de `cdktf` en Windows.
- **CLI/Deploy:** Se añadió lógica de reintento inteligente para errores de consistencia eventual (ej. `ConflictException`) durante despliegues de API Gateway.
- **Infra/CDKTF:** Se omite el CLI `cdktf synth`, generando módulos terraform directamente al invocar el punto de entrada de la aplicación.
- **Infra/Builder:** El constructor de infraestructura resuelve dinámicamente la región de AWS y el ID de cuenta desde `aetherion.config.ts`.
- **Infra/Builder:** Los despliegues del API Gateway ahora dependen estrictamente de todos los cambios de rutas/métodos asociados, forzando un redespliegue limpio cuando las rutas se actualizan.
- **Infra/Builder:** Las variables de entorno extensibles ahora se mapean correctamente desde `AetherionConfig` a través de `ControllerMetadata` a funciones Lambda individuales.

### Solucionado
- **Infra:** Se solucionó la generación del método OPTIONS de CORS al atar el ID único a la ruta (evitando rutas duplicadas).
- **Infra:** Se solucionó la falta de dependencias del `IntegrationResponse` hacia `MethodResponse` en API Gateway.
- **Infra:** El "Event Source Mapping" de SQS ahora utiliza correctamente el ARN real de la cola en vez de un string estático.
- **Infra:** Se genera un archivo `dummy.zip` local mediante `@cdktf/provider-archive` durante la síntesis para resolver los requisitos fuente del Lambda antes de compilar.
- **Core:** Se solucionaron los registros de rutas duplicadas al agregar validaciones directas dentro del decorador `@Route`.
- **Core:** Se añadió una validación durante el "synth-time" asegurando que todos los gateways de `@LambdaController` realmente apunten a un recurso `@ApiGateway` de infraestructura declarado.
