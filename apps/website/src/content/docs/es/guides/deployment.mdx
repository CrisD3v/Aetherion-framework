Desplegar una aplicación Aetherion implica sintetizar la definición de tu infraestructura en Terraform JSON y aplicarla a tu cuenta de AWS. Aetherion proporciona un flujo de trabajo optimizado para configurar tu entorno y desplegar con un solo comando.

## Configuración

Aetherion utiliza el archivo `aetherion.config.ts` ubicado en la raíz de tu proyecto para configurar el entorno de despliegue.

Este archivo exporta un objeto de configuración envuelto en el helper `defineConfig` para proporcionar tipado estricto y autocompletado en el IDE.

```typescript
// aetherion.config.ts
import { defineConfig } from '@aetherionfw/core';
import 'dotenv/config';

export default defineConfig({
  // Nombre de tu proyecto (usado como prefijo de recursos)
  projectName: 'my-aetherion-app',

  // Etorno de despliegue (dev, staging, prod)
  stage: process.env.AETHERION_STAGE ?? 'dev',

  // Tu AWS Account ID
  accountId: process.env.AWS_ACCOUNT_ID!,

  // Región de AWS objetivo
  region: process.env.AWS_REGION ?? 'us-east-1',

  // Perfil nominal de AWS CLI (opcional, usado para desarrollo local)
  profile: process.env.AWS_PROFILE ?? 'default',

  // Configuración base para todos los Lambdas
  lambdaDefaults: {
    runtime: 'nodejs20.x',
    memorySize: 256,
    envVars: {
      GLOBAL_VAR: 'value' // Inyectado en todas las funciones
    }
  }
});
```

### Variables de Entorno

Recomendamos utilizar variables de entorno (mediante un archivo `.env`) para información sensible y configuraciones específicas del entorno. La plantilla por defecto incluye `dotenv` para cargar estas variables automáticamente.

```env title=".env"
AWS_ACCOUNT_ID=123456789012
AWS_REGION=us-east-1
AWS_PROFILE=default
AETHERION_STAGE=dev
```

Al inicializar un proyecto con `aetherion init`, el framework generará automáticamente los archivos `.env` y `.env.example` con las variables requeridas. El uso de variables de entorno facilita la sobreescritura de la configuración en flujos de CI/CD sin necesidad de modificar el código fuente.

### Inyección de Variables con Menor Privilegio (Least Privilege)

Para cumplir estrictamente con las mejores prácticas de seguridad, **Aetherion no expone todas las variables del `.env` a cada función Lambda por defecto**. Si tu proyecto tiene 50 variables de entorno, inyectarlas todas en un endpoint público expondría una gran superficie de ataque. Además, AWS Lambdas cuenta con un límite estricto de 4KB para las variables de entorno.

En su lugar, Aetherion utiliza un mecanismo explícito de inyección de **Menor Privilegio** a través de la propiedad `envKeys` en tus decoradores:

```typescript
import { LambdaController, Handle, Route } from '@aetherionfw/core';

@LambdaController({
  lambdaName: 'payment-api',
  envKeys: ['STRIPE_SECRET_KEY'] // Sólo inyecta esta variable específica
})
export class PaymentController {
  
  @Handle({ envKeys: ['STRIPE_SECRET_KEY', 'WEBHOOK_SECRET'] }) // Sobrescribir por handler si es necesario
  @Route({ method: 'POST', path: '/webhook' })
  async handleWebhook() {
    // Procesar webhook
  }
}
```

Durante la síntesis (`aetherion deploy`), el framework buscará estas llaves en el `process.env` (que ha sido poblado por el `.env` local o por el runner en el CI/CD) y empaquetará **únicamente** esas variables específicas en la configuración de Terraform resultante para esa Lambda concreta.

## Validar Configuración

Antes de intentar un despliegue, puedes usar el comando `validate` para asegurar que todas las precondiciones, archivos `.env`, y construcciones existen y están correctos:

```bash
aetherion validate
```
Este comando verificará el estado de tu cuenta, la existencia de los binarios requeridos, y te dará un resumen rápido si algo falta.

## Verificación de Conexión AWS

Antes de desplegar, es muy recomendable verificar que Aetherion pueda conectarse a tu cuenta de AWS utilizando las credenciales configuradas.

Aetherion proporciona el comando `check-env`, que utiliza la acción `STS GetCallerIdentity` del SDK de AWS para validar tu conexión.

```bash
aetherion check-env
```

**Ejemplo de salida:**
```
✔ AWS connection verified successfully!

  Identity:
    Account : 123456789012
    UserId  : AIDAXXXXXXXXXXXXXXXXX
    ARN     : arn:aws:iam::123456789012:user/aetherion-deployer
    Region  : us-east-1
    Profile : default

  ✔ Account matches aetherion.config.ts (123456789012)
```

Si el ID de cuenta devuelto por AWS no coincide con el definido en tu `aetherion.config.ts`, el CLI mostrará una advertencia para evitar despliegues accidentales en la cuenta equivocada.

## Desplegar

Una vez configurado y verificado tu entorno, puedes proceder a desplegar tu aplicación. Aetherion se encarga de sintetizar la infraestructura CDKTF y ejecutar el despliegue en un solo paso.

```bash
aetherion deploy
```

El comando `deploy` es un "todo en uno" que realizará automáticamente los siguientes pasos:
1. Construirá tu proyecto TypeScript (`npm run build`).
2. Sintetizará la infraestructura CDKTF y generará los módulos de Terraform localmente.
3. Llamará a los binarios nativos de `terraform init` y `terraform apply` sin depender de emuladores intermedios.

También incluye lógica para realizar reintentos automáticos (retries) en caso de encontrar problemas de "Eventual Consistency" en AWS (particularmente con el API Gateway). Verás la salida en consola progresivamente, y al final obtendrás un resumen con las URLs y recursos creados.

### Otros Comandos Útiles

**Ver Estado:**
Para consultar qué infraestructura está desplegada actualmente, revisar sus configuraciones o recuperar el endpoint del API Gateway, usa:
```bash
aetherion status
```

**Destruir Infraestructura:**
Para limpiar y eliminar todos los recursos de AWS desplegados en este entorno, puedes utilizar:
```bash
aetherion destroy
```
Este comando te solicitará confirmación antes de proceder a borrar permanentemente el stack.

### Despliegue en CI/CD

Al desplegar desde un pipeline de CI/CD (como GitHub Actions), normalmente no utilizarás un perfil local de AWS. En su lugar, debes configurar roles de IAM o variables de entorno directamente en el runner (el entorno de ejecución).

En este caso, deja la variable `AWS_PROFILE` vacía y asegúrate de que `AWS_REGION` y `AWS_ACCOUNT_ID` estén configuradas en el entorno del pipeline.

```yaml title=".github/workflows/deploy.yml"
steps:
  - name: Configure AWS Credentials
    uses: aws-actions/configure-aws-credentials@v4
    with:
      role-to-assume: arn:aws:iam::123456789012:role/my-github-actions-role
      aws-region: us-east-1

  - name: Deploy Aetherion
    run: pnpm run deploy
    env:
      AWS_ACCOUNT_ID: 123456789012
      AWS_REGION: us-east-1
```
