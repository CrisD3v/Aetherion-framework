---
title: API Gateway Integration
description: How to configure REST and HTTP API Gateways in Aetherion using the @ApiGateway decorator.
---

Aetherion provides first-class support for AWS API Gateway. You can create new gateways or import existing ones, and the framework automatically wires your `@Route` decorators to the correct resources, methods, and integrations.

## Defining an API Gateway

Use the `@ApiGateway` property decorator inside an `@Infra` class to define your gateway:

```typescript
import { Infra, ApiGateway } from '@aetherionfw/core';

@Infra()
class AppInfra {
  @ApiGateway({
    name: 'main-api',
    type: 'REST',
    stageName: 'prod',
    corsEnabled: true,
  })
  mainApi: any;
}
```

### Configuration Options

| Option | Type | Default | Description |
|---|---|---|---|
| `name` | `string` | **required** | Unique name to identify this API Gateway |
| `type` | `'REST' \| 'HTTP'` | **required** | REST API (full control) or HTTP API (simpler, cheaper) |
| `description` | `string` | auto-generated | Description for the API resource |
| `stageName` | `string` | `'dev'` | Deployment stage name |
| `corsEnabled` | `boolean` | `true` | Enable CORS preflight responses (REST API) |
| `corsOrigins` | `string[]` | `['*']` | Allowed CORS origins |
| `existingApiId` | `string` | — | Import an existing API instead of creating one |
| `existingRootResourceId` | `string` | — | Root resource ID (required for existing REST APIs) |

## Linking Controllers to a Gateway

Use the `apiGateway` field in `@LambdaController` to bind a controller's routes to a specific API Gateway:

```typescript
import { LambdaController, Handle, Route } from '@aetherionfw/core';

@LambdaController({
  lambdaName: 'user-api',
  runtime: 'nodejs22.x',
  memorySize: 128,
  timeout: 5,
  apiGateway: 'main-api', // Must match an @ApiGateway name
})
export class UserController {
  @Handle()
  @Route({ method: 'GET', path: '/users' })
  async getUsers() {
    return { users: [] };
  }

  @Handle()
  @Route({ method: 'POST', path: '/users' })
  async createUser() {
    return { success: true };
  }

  @Handle()
  @Route({ method: 'GET', path: '/users/{id}' })
  async getUserById() {
    return { user: {} };
  }
}
```

### What Gets Generated

When you deploy, Aetherion's CDKTF builder automatically generates:

1. **API Gateway Resource** — `ApiGatewayRestApi` or `Apigatewayv2Api` depending on `type`.
2. **Hierarchical Resources** — For a path like `/users/{id}/orders`, three API Gateway resources are created: `/users`, `/users/{id}`, and `/users/{id}/orders`.
3. **Methods and Integrations** — Each `@Route` produces a method with an `AWS_PROXY` integration pointing to the corresponding 1:1 Lambda function.
4. **Lambda Permissions** — `lambda:InvokeFunction` is automatically granted to API Gateway for each integration.
5. **Deployment and Stage** — A deployment and stage are created with the configured `stageName`.
6. **CORS** — For REST APIs, an `OPTIONS` method with a MOCK integration is added to each resource when `corsEnabled` is true.

## REST vs HTTP API

| Feature | REST API | HTTP API |
|---|---|---|
| **Cost** | Higher | ~70% cheaper |
| **Latency** | Higher | Lower |
| **Authorizers** | Cognito, Lambda, IAM | JWT, Lambda |
| **API Keys** | Yes | No |
| **Request Validation** | Yes | No |
| **CORS** | Manual (auto-generated by Aetherion) | Built-in |
| **Use Case** | Production APIs with full control | Lightweight microservices |

```typescript
// REST API — full control, Cognito authorizers, API keys
@ApiGateway({ name: 'public-api', type: 'REST', stageName: 'prod' })
publicApi: any;

// HTTP API — cheaper, lower latency, auto CORS
@ApiGateway({ name: 'internal-api', type: 'HTTP', stageName: 'dev' })
internalApi: any;
```

## Using an Existing API Gateway

If you already have an API Gateway provisioned in your AWS account, you can import it instead of creating a new one:

```typescript
@Infra()
class AppInfra {
  @ApiGateway({
    name: 'legacy-api',
    type: 'REST',
    existingApiId: 'abc123xyz',
    existingRootResourceId: 'rootres123',
    stageName: 'prod',
  })
  legacyApi: any;
}
```

When `existingApiId` is provided:
- No new API Gateway resource is created.
- New routes, methods, and integrations are **added** to the existing API.
- The existing stage configuration is preserved.

> **Important**: You must provide `existingRootResourceId` for REST APIs. You can find it in the AWS Console under API Gateway, Resources, then the `/` (root) resource.

## Authorizers

Aetherion automatically wires Cognito authorizers when you reference a `@CognitoUserPool` in the `authorizer` field of `@Route`:

```typescript
@Infra()
class AppInfra {
  @CognitoUserPool({ name: 'app-users' })
  authPool: any;

  @ApiGateway({ name: 'secure-api', type: 'REST', stageName: 'prod' })
  api: any;
}

@LambdaController({
  lambdaName: 'order-api',
  apiGateway: 'secure-api',
})
export class OrderController {
  @Handle()
  @Route({ method: 'GET', path: '/orders' })
  async listOrders() {
    // Public endpoint — no authorizer
    return { orders: [] };
  }

  @Handle()
  @Route({ method: 'POST', path: '/orders', authorizer: 'app-users' })
  async createOrder() {
    // Protected — requires Cognito JWT token
    return { success: true };
  }
}
```

The framework:
1. Looks up the Cognito User Pool named `app-users` from the `@Infra` resources.
2. Creates an `ApiGatewayAuthorizer` of type `COGNITO_USER_POOLS`.
3. Attaches it to the `POST /orders` method.
4. Reuses the same authorizer for any other route referencing `app-users`.

## Troubleshooting

### "API Gateway not found for controller"

This warning means the `apiGateway` name in `@LambdaController` does not match any `@ApiGateway` `name` in your `@Infra` class. Double-check spelling and casing.

### "Authorizer references a Cognito User Pool that was not found"

The `authorizer` value in `@Route` must exactly match the `name` property of a `@CognitoUserPool` defined in an `@Infra` class.

### Routes not appearing in API Gateway

Ensure every route method has **both** `@Handle()` and `@Route()` decorators. A method with only `@Route` will not generate a Lambda function, so there is nothing to integrate.

### CORS errors in the browser

For REST APIs, Aetherion auto-generates `OPTIONS` methods when `corsEnabled: true` (default). If you still see CORS errors:
- Verify your frontend origin is included in `corsOrigins`.
- Check that your Lambda response includes `Access-Control-Allow-Origin` headers.
